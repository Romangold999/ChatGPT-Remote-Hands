# Android Remote Bridge

**Статус:** публичная проектная база и спецификация. Это ещё не готовый установщик.

Android Remote Bridge — универсальный установщик и локальная служба для подключения Android/Termux к ChatGPT и другим AI-ассистентам через индивидуальный приватный GitHub-репозиторий, GitHub Actions/OIDC и защищённый туннель.

## Главный принцип: публичный репозиторий абсолютно чистый

Публичный репозиторий содержит только универсальный код, шаблоны, документацию и тесты. Здесь никогда не должно быть пользовательских токенов, OAuth/PAT, OIDC JWT, паролей, SSH private keys, HMAC secrets, приватных конфигов, персональных tunnel URL, логов или результатов команд.

Каждый пользователь устанавливает проект заново. Bootstrap сам проверяет среду, проводит пользователя через необходимые подтверждения, создаёт индивидуальные ключи и конфигурацию, создаёт отдельный приватный operational repository и настраивает его. Никакие секреты разработчика или другого пользователя не копируются из шаблона.

## Что пользователь устанавливает

Обязательная основа:
- Android;
- Termux из выбранного официального источника.

Дополнительные приложения:
- **Termux:API** — только если включены функции, которым нужен доступ к Android API (например, уведомления, батарея, датчики или другие системные функции). Для работы нужны и приложение Termux:API, и пакет CLI `termux-api` внутри Termux.
- **Termux:Boot** — необязательный компонент для запуска пользовательского скрипта после перезагрузки Android. Устанавливается и настраивается только по отдельному согласию. Сам Bridge не должен включать автозапуск молча.

Все приложения Termux и плагины должны быть установлены из одного источника подписи (например, все из F-Droid или все из GitHub Releases). Нельзя смешивать APK из разных источников: подписи могут не совпасть.

## Цель установки

Пользователь запускает одну bootstrap-команду в Termux. Установщик:

1. Проверяет Android, ABI, Termux и доступность хранилища.
2. Определяет, нужны ли Termux:API и Termux:Boot для выбранных функций.
3. Устанавливает необходимые CLI-пакеты внутри Termux; Android APK-плагины устанавливаются отдельно из того же источника, что и Termux.
4. Проводит пользователя через GitHub CLI device/browser authorization. Токены не запрашиваются в чате и не печатаются в логах.
5. Создаёт индивидуальный приватный operational repository.
6. Генерирует уникальные SSH-ключи и локальные секреты на устройстве.
7. Настраивает GitHub Actions/OIDC, mailbox, локальный listener и выбранный tunnel provider.
8. Сохраняет локальную конфигурацию с ограниченными правами доступа и проверяет полный цикл команд.
9. Предлагает включить запуск после перезагрузки только как отдельный opt-in шаг.

## Разделение данных

| Где | Что хранится |
|---|---|
| Публичный репозиторий | Универсальный исходный код, шаблоны, документация, тесты. Никаких секретов и пользовательских данных. |
| Приватный репозиторий пользователя | Mailbox, workflow, индивидуальные несекретные параметры. Никаких private keys, PAT, OAuth tokens или OIDC JWT. |
| Локально на Android | GitHub CLI credential, SSH private key, HMAC/прочие локальные секреты, приватная конфигурация. Ограниченные права файлов; исключение из Git. |
| GitHub Actions | Краткоживущий OIDC token, автоматически получаемый на время workflow run. Не сохранять как постоянный secret. |

Установщик должен генерировать секреты на устройстве, а не скачивать готовые секреты из публичного репозитория. Private key никогда не покидает устройство. Публичный SSH key можно передать tunnel provider, если это требуется.

## Предполагаемый поток

AI assistant / разрешённый write channel → индивидуальный private GitHub repository → GitHub Actions/OIDC → tunnel → Termux Bridge → разрешённая команда → result mailbox → GitHub → AI assistant.

## Ограничения, которые нельзя скрывать

- GitHub connector в ChatGPT может быть read-only; возможности зависят от доступного пользователю подключения. Для записи нужен отдельный подтверждённый write-capable канал.
- HTTP 202 означает принятие webhook, а не завершение команды.
- Успешный workflow сам по себе не доказывает выполнение на телефоне: нужно проверить result mailbox.
- Бесплатные туннели могут менять URL, иметь лимиты, idle timeout и не гарантировать uptime.
- Android может ограничивать фоновые процессы; универсальная работа 24/7 не гарантируется даже с Termux:Boot.
- Авторизация может быть отозвана или потребовать повторного входа.
- Termux:API и Termux:Boot — отдельные Android-приложения-плагины; установка APK не заменяется командой `pkg install`.

## Планируемая структура

- `install.sh` — bootstrap для Termux.
- `src/` — bridge server, protocol и tunnel manager.
- `scripts/` — status/start/stop/logs/doctor/repair.
- `templates/` — чистые шаблоны operational repository и Actions workflow.
- `.github/workflows/` — CI и тесты публичного проекта.
- `docs/` — архитектура, auth, protocol, tunnel и troubleshooting.
- `SECURITY.md` — модель угроз.
- `tests/` — unit, integration и end-to-end tests.

## Принципы разработки

1. Отдельный приватный operational repository для каждого пользователя.
2. Минимальные GitHub permissions; OIDC для workflow вместо долгоживущего PAT в Actions.
3. Секреты генерируются и хранятся локально; не публикуются и не попадают в логи.
4. Команды сериализованы, имеют уникальные ID и sequence.
5. Большие файлы передаются частями, а не помещаются в одну команду.
6. Повторный запуск установщика безопасен и не затирает пользовательские данные.
7. Termux:Boot включается только по явному согласию.
8. Документация должна соответствовать реально протестированному коду.
9. Любая эталонная рабочая система остаётся read-only.
