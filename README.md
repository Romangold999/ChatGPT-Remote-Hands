# Android Remote Bridge

**Статус:** публичная проектная база и спецификация. Это ещё не готовый установщик.

Android Remote Bridge — открытый шаблон проекта для подключения Android/Termux к ChatGPT и другим AI-ассистентам через индивидуальный приватный GitHub-репозиторий, GitHub Actions/OIDC и защищённый туннель.

## Назначение

Пользователь с Android, Termux и GitHub должен получить понятную установку с минимумом ручных действий. В перспективе bootstrap проверяет среду, устанавливает только необходимые зависимости, помогает создать личный приватный репозиторий, настраивает локальный bridge, OIDC workflow и туннель, а затем проверяет полный обмен командами и результатами.

## Границы проекта

- Этот публичный репозиторий содержит только исходники, шаблоны и документацию.
- Каждый пользователь получает отдельный приватный operational repository.
- Существующие рабочие системы, использованные как read-only ориентир при проектировании, не входят в этот репозиторий и не должны изменяться или раскрываться.
- Не публиковать пользовательские конфиги, секреты, токены, SSH-ключи, логи, tunnel URL и результаты команд.

## Предполагаемый поток

1. Пользователь устанавливает поддерживаемый Termux.
2. Запускает bootstrap из этого репозитория.
3. Bootstrap проверяет Android/ABI и устанавливает минимальные зависимости.
4. GitHub CLI проводит пользователя через авторизацию; секреты остаются на устройстве.
5. Создаётся отдельный приватный репозиторий пользователя.
6. Установщик генерирует индивидуальную конфигурацию, Actions workflow и локальную службу.
7. Пользователь выполняет необходимые подтверждения у tunnel provider.
8. Проводится end-to-end проверка: AI assistant → GitHub → Actions/OIDC → tunnel → Termux → result → GitHub.

## Ограничения, которые нельзя скрывать

- GitHub connector в ChatGPT может быть read-only; возможности зависят от доступного пользователю подключения.
- Для записи команды нужен отдельный поддерживаемый write-capable канал.
- HTTP 202 означает принятие webhook, а не завершение команды.
- Успешный workflow сам по себе не доказывает выполнение на телефоне: нужно проверить result mailbox.
- Бесплатные туннели могут менять URL, иметь лимиты, idle timeout и не гарантировать uptime.
- Android может ограничивать фоновые процессы; универсальная работа 24/7 не гарантируется.
- Авторизация может быть отозвана или потребовать повторного входа.

## Планируемая структура

- `README.md`, `README_EN.md` — инструкции.
- `CHATGPT_PROMPT_RU.md`, `CHATGPT_PROMPT_EN.md` — мастер-промпты.
- `install.sh` — bootstrap для Termux.
- `src/` — bridge server, protocol и tunnel manager.
- `scripts/` — status/start/stop/logs/doctor/repair.
- `.github/workflows/` — workflow с минимальными permissions.
- `docs/` — архитектура, auth, protocol, tunnel и troubleshooting.
- `SECURITY.md` — модель угроз.
- `tests/` — unit, integration и end-to-end tests.

## Принципы разработки

1. Отдельный приватный operational repository для каждого пользователя.
2. Минимальные GitHub permissions; OIDC для workflow вместо долгоживущего PAT в Actions.
3. Секреты остаются на устройстве и не попадают в логи.
4. Команды сериализованы, имеют уникальные ID и sequence.
5. Повторный запуск установщика безопасен и не затирает пользовательские данные.
6. Разрушительные действия требуют явного подтверждения.
7. Документация должна соответствовать реально протестированному коду.
8. Любая эталонная рабочая система остаётся read-only.
