> **Текущий статус:** реализован начальный локальный Bridge runtime (OIDC, replay/sequence state, безопасный allowlist executor) и шаблон приватного operational repo. Универсальный установщик, tunnel manager и end-to-end проверка ещё разрабатываются. Это не production-ready релиз.

## Что это

Android Remote Bridge — открытый проект для создания персонального канала, через который AI-ассистент может отправить разрешённую команду на Android-устройство с Termux и получить результат.

Проект рассчитан на индивидуальную установку: **каждый человек создаёт и использует только свою инфраструктуру**. Никаких общих серверов, чужих телефонов или подключения к инфраструктуре автора.

## Как устроено подключение

```text
                 ПУБЛИЧНЫЙ ПРОЕКТ
                Android-Remote-Bridge
          исходники · установщик · шаблоны · docs
                           |
                     установка копии
                           v
        +---------------------------------------+
        |            ПОЛЬЗОВАТЕЛЬ А             |
        |                                       |
 AI --->| свой PRIVATE GitHub repository        |
        |          |                            |
        |      GitHub Actions + OIDC            |
        |          |                            |
        |      личный защищённый tunnel         |
        |          |                            |
        |      Bridge в своём Termux            |
        |          |                            |
        |      результат в своём repo           |
        +---------------------------------------+

        Пользователь Б разворачивает отдельную,
        независимую копию всей своей инфраструктуры.
```

Публичный репозиторий — это **исходный проект**, а не центральный сервер. После установки команды и результаты проходят через индивидуальный приватный репозиторий пользователя, его Android-устройство и его tunnel.

## Главное правило безопасности

В этом публичном репозитории хранятся только универсальные исходники, чистые шаблоны, документация и тесты.

**Здесь никогда не должно быть:**
- GitHub PAT, OAuth credentials, паролей и сессионных токенов;
- OIDC JWT и других временных bearer-токенов;
- SSH private keys, HMAC secrets и приватных конфигураций;
- персональных tunnel URL, адресов локальных служб и приватных endpoint;
- пользовательских логов, mailbox, результатов команд и дампов устройств.

Секреты создаются на устройстве пользователя. Его SSH private key остаётся на устройстве. В приватный GitHub-репозиторий попадают только необходимые несекретные файлы. GitHub Actions получает короткоживущий OIDC-токен во время запуска workflow — он не сохраняется как постоянный секрет.

Подробности: [Модель безопасности](SECURITY.md).

## Что понадобится

### Обязательно
- Android-устройство с поддерживаемой архитектурой; первый целевой профиль — ARM64.
- Termux из официального источника.
- GitHub account.
- Сеть для доступа к GitHub и выбранному tunnel provider.
- AI-ассистент и канал, который действительно может записывать команды в приватный mailbox. Возможности GitHub connector в ChatGPT могут быть только read-only.

### Дополнительные приложения
- **Termux:API** — необязательно. Нужен только для функций, которым требуется доступ к Android API. Помимо Android-приложения плагина, внутри Termux устанавливается CLI-пакет `termux-api`.
- **Termux:Boot** — необязательно. Нужен только для попытки запуска Bridge после перезагрузки. Включается отдельно, только по согласию владельца устройства.

Termux и все его плагины должны быть установлены из одного совместимого источника подписи (например, все из F-Droid либо все из GitHub Releases). Не смешивайте APK из разных источников.

## Что будет делать установщик

Целевой сценарий — одна команда в Termux с пошаговым подтверждением:

1. Проверить Android, ABI, Termux, свободное место и сеть.
2. Установить необходимые CLI-зависимости.
3. Провести пользователя через GitHub CLI device/browser authorization.
4. Создать **новый приватный репозиторий именно этого пользователя** и загрузить туда чистый operational template.
5. Сгенерировать индивидуальные ключи и локальные секреты на устройстве.
6. Настроить GitHub Actions/OIDC и выбранный tunnel provider.
7. Установить и запустить локальный Bridge.
8. Выполнить безопасный тест и проверить не только запуск workflow, но и фактический результат.
9. Предложить Termux:Boot отдельным необязательным шагом.

Установщик не должен подключать пользователя к репозиторию автора или к Bridge другого человека. Он также не должен молча менять существующие пользовательские файлы.

## Принципы проекта

- **One user — one private Bridge:** отдельный приватный operational repo и отдельная установка для каждого владельца.
- **No shared secrets:** никакие секреты автора не копируются пользователям.
- **Least privilege:** минимальные GitHub permissions и ограниченный набор разрешённых операций.
- **OIDC, not stored JWT:** краткоживущая идентификация workflow вместо постоянного токена в Actions.
- **Local-first secrets:** private keys и локальные секреты остаются на Android.
- **Safe by default:** подтверждения для рискованных действий, таймауты, лимиты вывода и защита от повторного выполнения.
- **Resumable setup:** повторный запуск установщика не должен терять конфигурацию или затирать пользовательские данные.
- **Honest status:** документация и README отражают только то, что реально реализовано и протестировано.

## Важные ограничения

- GitHub connector в ChatGPT может не поддерживать запись. Нужен подтверждённый write-capable канал.
- HTTP 202 означает, что webhook принят, но не то, что команда выполнена.
- Успешный GitHub Actions run не доказывает выполнение на телефоне: нужно проверить result mailbox.
- Бесплатные туннели могут менять адрес, ограничивать трафик или отключаться по idle timeout.
- Android может останавливать фоновые процессы. Работа 24/7 не гарантируется.
- GitHub authorization может быть отозвана и потребовать повторного входа.
- Termux:API и Termux:Boot — отдельные приложения-плагины; `pkg install` не устанавливает их APK.
