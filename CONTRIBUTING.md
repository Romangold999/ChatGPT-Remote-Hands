# Участие в проекте

Спасибо за интерес к Android Remote Bridge. Сейчас проект находится на стадии разработки базовой архитектуры и безопасного bootstrap.

## Перед изменениями

1. Прочитайте [README](README.md).
2. Изучите [архитектуру](docs/ARCHITECTURE.md), [дорожную карту](docs/ROADMAP.md) и [модель безопасности](SECURITY.md).
3. Убедитесь, что изменение не нарушает принцип «один пользователь — один приватный Bridge».
4. Для нового каталога или важного файла обновите [карту структуры](docs/PROJECT_STRUCTURE.md).

## Правила безопасности

Никогда не добавляйте в Pull Request, Issue, Discussion или тестовый fixture:

- GitHub PAT, OAuth credentials, пароли или cookies;
- OIDC JWT и другие bearer tokens;
- SSH private keys, HMAC secrets или приватные конфиги;
- реальные tunnel URL, публичные endpoint локального listener;
- реальные command/result mailbox, пользовательские логи или дампы.

Для тестов используйте только синтетические данные и специально созданные тестовые ключи. Не прикладывайте вывод диагностики, пока не проверили его на секреты и персональные данные.

Если обнаружили уязвимость, не публикуйте exploit и секретные данные в открытом Issue. Следуйте инструкции из [SECURITY.md](SECURITY.md).

## Ожидания к изменениям

- Изменение должно решать одну понятную задачу.
- Не добавляйте новые зависимости без объяснения необходимости.
- Не отключайте TLS/SSH host verification ради «починки».
- Не расширяйте GitHub permissions без обоснования.
- Не выполняйте произвольные shell-команды из непроверенного mailbox.
- Добавляйте тесты на нормальный сценарий и отказ/ошибку.
- Обновляйте документацию вместе с поведением кода.
- Не заявляйте поддержку устройства/провайдера без проверки.

## Стиль Pull Request

Опишите:
1. Что меняется и зачем.
2. Какие файлы затронуты.
3. Как проверяли изменение.
4. Какие риски или ограничения остаются.
5. Какие новые permissions/dependencies добавлены и почему.

До появления CI все проверки должны быть явно описаны в PR. Не выдавайте непроверенный код за production-ready.
