# Протокол команд mailbox

Документ описывает начальную версию протокола и границы текущей реализации. Наличие валидатора JSON **не означает**, что команда уже аутентифицирована, принята к выполнению или может безопасно исполняться.

## Файлы приватного operational repository

- `mailbox/command.json` — входящая команда.
- `mailbox/result.json` — результат последней команды.
- `status/tunnel-url.txt` — текущий tunnel endpoint (только в приватном operational repository; персональный URL не публикуется).

## Envelope версии 1

Обязательные поля:

| Поле | Тип | Правило |
|---|---|---|
| `version` | integer | строго `1` |
| `id` | string | canonical UUID |
| `sequence` | integer | положительное число; монотонность проверяется persistent state слоем |
| `operation` | string | только operation из allowlist |

Дополнительные поля:

| Поле | Тип | Правило |
|---|---|---|
| `status` | string | для новой команды только `pending` |
| `arguments` | object | в первой версии операции не принимают аргументы |
| `approval` | boolean | по умолчанию `false`; само по себе не является подтверждением опасной операции |
| `timeout_seconds` | integer | от 1 до 60; значение по умолчанию 10 |

Лимит входного JSON envelope — 16 KiB. Неизвестные поля отклоняются.

### Начальный allowlist

- `bridge.status`
- `bridge.health`
- `system.info`

Это имена операций для следующего слоя реализации. Валидатор протокола пока только проверяет envelope; он **не выполняет** эти операции.

Произвольное поле `command`, shell-строка или операция `shell.exec` не поддерживаются. Новая операция добавляется только вместе с реализацией, схемой аргументов, тестами, документацией и security review.

## Поля результата

Целевая структура результата:

- `version`
- `id`
- `sequence`
- `status`
- `started_at`
- `finished_at`
- `exit_code`
- `stdout`
- `stderr`
- `error`

Результат должен быть ограничен по размеру. Секреты, токены и приватная конфигурация не должны попадать в stdout/stderr/result.

## Правила обработки

- Одна активная команда одновременно.
- Уникальный ID для каждой команды.
- Монотонный sequence, проверяемый persistent local state.
- Перед записью новой команды проверить предыдущую и получить актуальный blob SHA.
- Не повторять ID и не переиспользовать устаревший SHA.
- После dispatch отдельно проверять result mailbox.
- HTTP 202 — только принятие webhook, а не завершение команды.
- Ограничивать размер сообщения, время выполнения и размер результата.
- Для больших файлов использовать chunked transfer с проверкой SHA-256, порядка частей, общего размера и TTL.

## Обязательные security gates перед выполнением

1. Проверить подпись и claims GitHub OIDC: issuer, audience, repository, ref и timestamps.
2. Проверить replay protection и уникальность ID.
3. Проверить sequence относительно локального persistent state.
4. Проверить allowlist операции и строгую схему её аргументов.
5. Применить timeout, лимит вывода и минимальные права процесса.
6. Записать terminal result и только после этого сообщать об успешном выполнении.

Текущий код реализует только синтаксическую проверку envelope. OIDC, replay/sequence state, исполнитель и mailbox transport остаются отдельными задачами дорожной карты.
