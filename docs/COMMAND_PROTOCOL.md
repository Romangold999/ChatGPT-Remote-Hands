# Mailbox command protocol

Этот документ описывает целевой протокол новой версии. Полная схема должна быть закреплена тестами до выпуска.

## Предлагаемые файлы

- `mailbox/command.json` — входящая команда.
- `mailbox/result.json` — результат последней команды.
- `status/tunnel-url.txt` — текущий tunnel endpoint (только в приватном operational repository).

## Поля команды

- `version`
- `id`
- `sequence`
- `status`
- `operation`
- `approval`
- `timeout_seconds`
- `command` или структурированные аргументы операции

## Поля результата

- `version`
- `id`
- `sequence`
- `status`
- `started_at`
- `finished_at`
- `exit_code`
- `stdout`
- `stderr`
- `error`

## Правила

- Одна активная команда одновременно.
- Уникальный ID для каждой команды.
- Монотонный sequence, проверяемый локальным состоянием.
- Перед записью новой команды проверить предыдущую и получить актуальный blob SHA.
- Не повторять ID и не переиспользовать устаревший SHA.
- После dispatch отдельно проверять result mailbox.
- HTTP 202 — только принятие webhook.
- Ограничивать размер сообщения, время выполнения и размер результата.
- Для больших файлов использовать chunked transfer или отдельное хранилище; не пытаться помещать весь payload в поле command.
- Проверять целостность частей (например, SHA-256), порядок, общий размер и срок жизни незавершённой передачи.

## Безопасность

По умолчанию не разрешать произвольное выполнение shell-команд. Предпочтительны структурированные операции и allowlist. Учитывать рабочий каталог, права процесса, timeout, лимит вывода и журнал аудита. Секреты не должны попадать в stdout/result.
