# Дорожная карта

Статусы отражают состояние публичного репозитория, а не обещание сроков.

## Этап 0 — проектная база

- [x] Зафиксировать архитектуру «один пользователь — один приватный Bridge».
- [x] Описать границы публичного и приватного репозиториев.
- [x] Описать хранение секретов и GitHub OIDC.
- [x] Описать требования Termux:API и Termux:Boot.
- [x] Добавить навигацию по документации и карту структуры.
- [ ] Добавить выбранную лицензию после отдельного решения автора.

## Этап 1 — минимальный исполняемый Bridge

- [ ] Определить поддерживаемую версию Python и зависимости для Termux.
- [ ] Реализовать локальный listener с привязкой только к loopback.
- [ ] Реализовать строгую схему command/result mailbox.
- [ ] Добавить проверку размера, формата, ID, sequence и срока действия команды.
- [ ] Добавить allowlist операций, таймауты и лимиты stdout/stderr.
- [ ] Реализовать безопасный lifecycle: status/start/stop/logs.
- [ ] Написать unit tests и тесты отказа по умолчанию.

**Критерий выхода:** локальный Bridge работает в чистом Termux и не выполняет неизвестные или некорректные команды.

## Этап 2 — приватный operational repository

- [ ] Создавать отдельный private repo в аккаунте самого пользователя.
- [ ] Проверять владельца и приватность созданного репозитория.
- [ ] Загружать только чистый template.
- [ ] Создавать минимальный workflow с permissions по принципу least privilege.
- [ ] Закреплять сторонние Actions на immutable commit SHA.
- [ ] Исключить PAT/OAuth credentials/private keys из operational repo.

**Критерий выхода:** две тестовые учётные записи получают независимые приватные репозитории; конфигурации и mailbox не пересекаются.

## Этап 3 — OIDC и защищённый tunnel

- [ ] Проверить актуальные варианты tunnel provider и их условия.
- [ ] Сгенерировать уникальный ключ на Android.
- [ ] Передавать провайдеру только public key, если это требуется.
- [ ] Проверять host key/fingerprint и не отключать проверку SSH host.
- [ ] Валидировать OIDC signature, issuer, audience, repository, ref, timestamps и replay.
- [ ] Реализовать reconnect и безопасное обновление изменившегося tunnel endpoint.

**Критерий выхода:** listener принимает запросы только от workflow конкретного private repo и отклоняет неверные claims/повторные запросы.

- [ ] Сделать идемпотентный `install.sh` для Termux ARM64.

- [ ] Использовать GitHub CLI browser/device flow.
- [ ] Генерировать локальные секреты и сохранять их с ограниченными правами.
- [ ] Реализовать безопасный resume после прерывания.
- [ ] Добавить проверку состояния и диагностику.
- [ ] Добавить Termux:API как optional feature.

**Критерий выхода:** установка с нуля и повторное продолжение после искусленного прерывания проходят на чистом поддерживаемом устройстве.

## Этап 5 — передача больших данных и release

- [ ] Реализовать chunked transfer с hash/integrity checks, лимитами и TTL.
- [ ] Проверить прерывание/повтор/дубликаты частей.
- [ ] Провести end-to-end тест на отдельной тестовой инфраструктуре.
- [ ] Добавить CI, статический анализ и security checks.
- [ ] Опубликовать release notes, проверенную инструкцию установки и список ограничений.

**Критерий выхода:** полный сценарий подтверждён тестами; README и docs описывают только реально доступные функции.

## Не входит в обещания проекта

- Гарантированный uptime 24/7 на Android.
- Неограниченный бесплатный tunnel.
- Постоянная GitHub авторизация без повторных подтверждений.
- Автоматическая запись через read-only GitHub connector.
- Выполнение произвольных команд без ограничений.
