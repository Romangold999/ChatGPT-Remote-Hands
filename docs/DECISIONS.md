# История решений и контекст проекта

## Почему универсальный проект

Цель — воспроизводимая связка на чистом Termux для разных пользователей Android, а не отдельное APK-приложение. Основной UX — одна bootstrap-команда, минимум ручных действий и понятные подтверждения.

## Неприкосновенность эталонов

Существующие рабочие системы остаются read-only. Их файлы, конфигурации, секреты, процессы, репозитории и настройки не изменяются. В публичный проект не копируются персональные данные или точные конфигурации.

## Публичный и приватный контуры

- Публичный репозиторий — только универсальные исходники, чистые шаблоны, документация и тесты.
- Публичный репозиторий никогда не содержит токены, пароли, SSH private keys, HMAC secrets, приватные конфиги, пользовательские tunnel URL, логи или результаты.
- Для каждого пользователя создаётся отдельный private operational repository.
- Секреты и уникальные ключи генерируются на устройстве во время bootstrap; приватный ключ не покидает устройство.
- Private operational repository содержит mailbox, workflow и только необходимые несекретные параметры.
- Actions получает краткоживущий OIDC JWT на время workflow run; не сохранять JWT как постоянный secret.

## Архитектурные решения

- GitHub CLI предпочтительнее ручного PAT copy/paste, но авторизация может требовать повторного входа.
- OIDC token проверяется локально по подписи и claims.
- Результат команды проверяется отдельно; workflow success не является подтверждением выполнения.
- Mailbox сериализован: одна активная команда одновременно.
- Для больших данных используется chunked transfer или отдельное хранилище.
- ChatGPT connector может быть read-only; write path должен быть подтверждён отдельно.
- Tunnel provider может менять URL и ограничивать бесплатный доступ.
- Android может завершать фоновые процессы; 24/7 uptime не обещается.

## Termux plugins

- Termux:API не обязателен для базового Bridge. Подключается, когда реализованы конкретные Android API функции; для него нужны plugin APK и CLI package `termux-api`.
- Termux:Boot необязателен и включается только после отдельного opt-in. Нельзя автоматически создавать boot scripts или включать wake lock без согласия.
- Termux и plugins должны быть из одного источника подписи; установщик обязан проверить совместимость и предупредить о смешанных источниках.

## UX и безопасность

- Максимально автоматизированная установка с понятными сообщениями.
- Минимум зависимостей; устанавливать только то, что реально требуется.
- Идемпотентность и возможность продолжить установку после прерывания.
- Backup перед изменением пользовательских файлов.
- Не выполнять destructive operations без явного подтверждения.
- Команды status/start/stop/logs/doctor/repair должны быть реализованы и протестированы до документирования как доступные.
