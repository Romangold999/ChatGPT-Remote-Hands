# История решений и контекст проекта

## Почему универсальный проект

Цель — воспроизводимая связка на чистом Termux для разных пользователей Android, а не отдельное APK-приложение. APK признан избыточным усложнением на первом этапе. Основной UX — одна bootstrap-команда, минимальные интерактивные подтверждения и мастер-промпт AI assistant.

## Неприкосновенность эталонов

Существующие рабочие системы, использованные при проектировании, остаются read-only. Их файлы, конфигурации, секреты, процессы, репозитории и настройки не изменяются. В публичный проект не копируются их персональные данные или точные конфигурации.

## Архитектурные решения

- Пользовательский operational repository должен быть приватным и индивидуальным.
- Публичный репозиторий содержит только универсальный код, шаблоны и документацию.
- Для доставки событий рассматривается push-based workflow с OIDC.
- OIDC token проверяется локально по подписи и claims.
- Результат команды проверяется отдельно; workflow success не является подтверждением выполнения.
- Mailbox сериализован: одна активная команда одновременно.
- Для больших данных проектируется chunked transfer или отдельное хранилище; искусственно увеличивать лимит одного command JSON — не основное решение.
- ChatGPT connector может быть read-only; write path должен быть подтверждён отдельно.
- GitHub CLI предпочтительнее ручного PAT copy/paste, но сроки действия, scopes и policy должны быть проверены.
- Tunnel provider может менять URL и ограничивать бесплатный доступ.
- Android может завершать фоновые процессы; 24/7 uptime не обещается.

## UX и безопасность

- Максимально автоматизированная установка с понятными сообщениями для новичка.
- Минимум зависимостей; не переносить посторонние пакеты из тестовой среды.
- Идемпотентность и возможность продолжить установку после прерывания.
- Backup перед изменением пользовательских файлов.
- Не включать Termux:Boot без отдельного согласия.
- Не выполнять destructive operations без явного подтверждения.
- Команды status/start/stop/logs/doctor/repair должны быть реализованы и протестированы до документирования как доступные.
